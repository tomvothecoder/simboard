# Plan: Archive metadata and source-preserving model dates

## Scope

Implement and verify each logical group before committing it and starting the next.

1. **#420 component sets:** read the required long name from XML `COMPSET` and
   optional alias from README. Align nullable storage and contracts, check long-name
   capacity, and add guarded, source-backed repair to the existing backfill workflow.
2. **#420 grids:** read the required resolved specification from XML `GRID` and
   optional resolution alias from README. Align nullable storage and contracts and
   extend source-backed repair to grid fields.
3. **#420 legacy flags:** support single/double-dash component-set and resolution
   flags, including assignment forms, without erasing required XML metadata.
4. **#420 Git remotes:** normalize only known SSH-to-HTTPS mappings. Preserve raw
   remotes separately; leave HTTP URLs unset for local and unsupported remotes.
5. **#418 model dates:** store validated, canonical `YYYY-MM-DD` strings as text.
   Preserve source year/month/day, including year zero, without calendar conversion.
   Keep coupler-clock precedence and existing continuation fallback rules. Use only
   explicit source end dates; remove inferred `STOP_N` arithmetic. Keep real run
   timestamps unchanged. Update storage, API, backfill, exports, and display.

Each item is its own commit, including tests, migrations, and relevant documentation.

## Constraints

- Do not swap existing values blindly or expect duplicate ingestion to repair them.
- Reuse backfill identity checks, dry runs, expected-value guards, and audit history.
- Do not apply production repairs, run archive-wide ingestion, or change recovery
  and discovery behavior covered by separate issues.
- Preserve unrelated staged and unstaged work.
- Model-date checks validate structure and basic month/day ranges, not Gregorian
  calendar membership. Never shift year zero or discard unsupported values silently.

## Acceptance criteria

- Required XML metadata and optional README aliases survive storage/API round trips.
- Legacy flags parse, Git provenance survives, and source-backed repair is idempotent.
- Year-zero dates survive parser, database, API, and frontend round trips unchanged.
- Missing explicit simulation end dates remain null.

## Validation

Run focused tests for each group, `make backend-test`, `make frontend-lint`, and
root-level `make pre-commit-run` before each commit. Run `make frontend-build` when
frontend contracts change. Use the isolated test PostgreSQL database for migrations
and API tests. Repeat combined checks after all groups and review the final changes.
Report unavailable checks rather than claiming success. Archive reproductions are
read-only and require archive access.
